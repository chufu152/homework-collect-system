# 前端阶段 A 成果：六页 surface brief 与设计系统清点

> 依据 `docs/frontend-skill-prompts.md` 的 A1、A2 提示词产出，调用 `impeccable` 的 `init` + `shape`（简报）与 `document` + `extract`（只做清点、不做抽取迁移）流程。
> 本文件是**只读分析成果**：未修改任何 `apps/web` 文件，未新建/替换视觉世界，未写方向契约。
> 所有事实来自 `apps/web/src/**` 与 `docs/api.md` 等既有文档；需要用户拍板的内容统一进入「待确认」。

## A1 — 六条路由的 surface brief

六条路由均判定为 **Operate** 模式：访客都是来「完成一件事」，所需的是可扫读性、一致性与熟悉的控件，不是说服力或展示性。学生端虽然是对外可访问的公开链接，仍是任务界面，不是 Persuade 落地页。

### 1. `/` — 教师首页（作业列表）· `TeacherHomeView.vue`

- **任务与使用者**：持有管理令牌的教师；进入后先判断「今天哪些作业在收、还差多少人」，再进入某条作业或去发布/设置班级。
- **结果与证据**：作业总数、正在收取、应完成人次、尚未完成四项统计；作业列表含类型、截止时间、状态、`已完成/应交`、`未完成`；`published` 作业可一键复制分享链接。
- **方向**：沿用既有 `styles.css` 视觉世界，不新建方向契约（T5 待确认）。
- **范围与边界**：保留 topbar 导航与「发布作业」入口；不改路由；不新增统计口径；公开数据不得出现。
- **状态与数据范围**：已有 loading / 读取失败（引导去设置班级与密钥）/ 空列表（引导建立名单或发布）/ 列表；剪贴板可用与不可用两种提示。列表按 `GET /assignments?pageSize=100` 拉取，单班规模。
- **交互与层级**：统计卡 → 列表标题 → 列表；窄屏隐藏部分指标并显示 `mobile-summary`。
- **约束与待确认**：错误提示沿用统一 message；是否对 429/503 做差异化提示（T8）。

### 2. `/class/setup` — 班级设置 · `ClassSetupView.vue`

- **任务与使用者**：教师；首次使用按顺序完成「保存管理密钥 → 建立唯一班级 → 导入名单 → 整理分组」。
- **结果与证据**：班级唯一且已存在时显示学生数与分组列表；名单导入返回新增/更新/被拒行号；分组返回组名与人数。
- **方向**：同上，沿用既有视觉世界。
- **范围与边界**：不引入账号/密码；管理密钥只进 `sessionStorage`；不在页面回显令牌；不新增分组策略。
- **状态与数据范围**：密钥保存中/已保存；班级未创建 / 已创建两条分支；名单解析预览（最多显示 8 行）、格式错误行、导入中、导入成功与部分拒绝；均分随机 / 手动两种分组；无学生时禁用分组。名单以「每行 学号 姓名」输入，受 JSON 请求体 100 KB 默认上限约束（单班规模）。
- **交互与层级**：密钥表单 → 建班或导入 → 分组；窄屏把两列字段与单选项堆叠。
- **约束与待确认**：重复学号更新姓名、组内成员校验由后端决定，前端不另造规则；错误码 409/400 的文案粒度（T8）。

### 3. `/assignments/new` — 新建/发布作业 · `AssignmentCreateView.vue`

- **任务与使用者**：教师；设定作业类型、收取内容、截止时间与目标名单，发布后拿到学生分享链接。
- **结果与证据**：`draft` 或 `published` 结果、`expectedCount` 目标人数、分享链接；页面明示「本次作业将固定 N 位目标同学」。
- **方向**：同上。
- **范围与边界**：四种类型与三种目标模式既有，不新增；`submissionMode` 仅对 `online` 生效；不改接口请求体结构。
- **状态与数据范围**：班级读取中 / 班级不存在（引导设置）/ 表单；目标为空、分组未选、姓名为空等本地校验；保存中；成功（已发布/草稿、复制链接、打开看板）；剪贴板不可用。附件规则沿用 `allowedFileTypes` 白名单、单文件 ≤20 MB、≤5 个（前端展示值）。
- **交互与层级**：作业名称 → 说明 → 类型 → 目标 → 收取内容 → 截止时间 → 发布开关 → 结果。
- **约束与待确认**：类型/状态术语须与 `docs/api.md` 一致；是否新增任何依赖或组件库（T7 = 否，按 C5）。

### 4. `/assignments/:assignmentId` — 教师看板 · `AssignmentDashboardView.vue`

- **任务与使用者**：教师；查看谁交了、批改、下载附件、导出，并在需要时发布/停止收取。
- **结果与证据**：`summary` 四项统计、`missingMentionText` 未完成名单、`items` 每位目标学生的状态/提交时间/文本/附件/分数与反馈；分享链接；CSV/ZIP/DOCX 导出。
- **方向**：同上；`DESIGN.md` 作为一致性基准。
- **范围与边界**：`closed` 不可重开；仅 `published` 可关闭；非目标学生不出现在 `items`；不新增导出格式；下载仍走 Blob + `Content-Disposition` 解码。
- **状态与数据范围**：loading / 看板不可用（引导检查密钥）/ 数据；`draft` 显示发布按钮、`published` 显示停止收取；线上类型才有评分反馈与 Word 导出、ZIP 导出；线下类型用复选框登记完成（可撤销）；`feedback: null` 未批改；桌面表格与 `mobile-student-list` 两套渲染，窄屏隐藏表格。ZIP 受 `MAX_EXPORT_BYTES` 200 MB 上限。
- **交互与层级**：返回 → 标题/状态 → 统计 → 工具栏 → 未完成名单 → 学生明细。
- **约束与待确认**：版本历史 UI 是否落在此页、以及展示形态（T1/T2）；历史附件下载复用 3.14（C2 只出方案）。

### 5. `/a/:shareCode` — 学生作业页 · `StudentAssignmentView.vue`

- **任务与使用者**：持分享链接的学生；按作业类型提交线上作业、签到、加入接龙，或看到「线下作业」说明。
- **结果与证据**：作业标题/说明/截止时间；提交后拿到 `receiptCode` 并跳转回执；接龙显示稳定序号名单；签到幂等提示。
- **方向**：同上；此页是任务页，不应用任何 hero/照片/高光时刻类营销规则。
- **范围与边界**：公开接口只暴露单条作业信息，不渲染全班名单；无效 `shareCode` 统一 404 语义；不新增身份字段。
- **状态与数据范围**：打开中 / 暂时无法打开（可重新加载）/ 数据；`online`（`text`/`file`/`both` 三种模式）、`checkin`、`relay`、`offline` 分支；发送中、成功、错误、确认、`再次提交 / 修改`；接龙空态与重复占位 409；同名需学号消歧；`textContent` 上限 20000 字符、附件 0–N 个受数量/大小/白名单/内容签名校验。
- **交互与层级**：作业信息 → 表单 → 结果/回执入口 → 接龙名单（仅 relay）。
- **约束与待确认**：错误文案须覆盖 400/404/409/413/429/503（T8）；不在 URL 展示或文案中泄露 `shareCode`/`receiptCode`（C7）。

### 6. `/receipt/:receiptCode` — 学生回执页 · `StudentReceiptView.vue`

- **任务与使用者**：学生；用回执链接查看本人最新提交内容、下载附件、查看教师反馈。
- **结果与证据**：提交时间与版本号、文本、附件（名称/大小）、教师反馈（分数 + 文字）；页面明示保存链接以便复查。
- **方向**：同上。
- **范围与边界**：只读本人提交；不展示全班名单；无效回执码统一 404；下载走 4.7 且带 `receiptCode`。
- **状态与数据范围**：读取中 / 无法打开（可重新加载）/ 数据；无文本、无附件、未批改（`feedback: null`）；下载中；下载失败提示。**已知缺口**：后端 4.6 已追加 `versions`，但 `client.ts` 的 `StudentReceipt` 类型与本页面尚未消费。
- **交互与层级**：品牌行 → 成功标题 → 提交内容 → 附件 → 教师反馈 → 回执码。
- **约束与待确认**：是否在此页展示历次修改（T2/T3）；回执码在页面明文展示属既有设计，是否需调整（C7 的边界解释待确认）。

### 一次性实现 / 需人工判断的漂移（只记录，不修）

- **硬编码颜色**：`styles.css` 第 28 行之后共出现 51 处十六进制颜色、39 个不同值，未收敛到 `:root` token（如 `#b6cbc4`、`#d1e5de`、`#536467`、`#bf9140`、`#89669a`、`#438d7d`、`#528d7d` 等）。
- **圆角不成体系**：`border-radius` 共 12 种取值（10px ×6、9px ×4、13px ×2、11px ×2，以及 7/8/12/16/50%/999px 与 `11px 11px 11px 3px`），`:root` 只定义了 `--radius: 16px` 且仅被 1 处引用。
- **内联样式**：6 个视图共 18 处 `style="…"`，多为 margin / max-width / padding 的一次性覆盖。
- **控件尺寸**：`.button` `min-height: 42px`、表单控件 `min-height: 43px`、`.icon-button` 为 `36×36px`；相对 44px 触摸目标存在差距（是否按间距例外判定，需 D2 实测）。
- **流体标题**：h1 使用 `clamp(28px, 4vw, 40px)` 与公有页 `clamp(27px, 7vw, 37px)`；与 impeccable `operate.md` 的「产品界面用固定 rem 字号阶梯」存在方向差异。
- **标题上方小标签**：`.eyebrow` 出现 14 次；与 impeccable `craft-floor.md` 中标为 ban 的「heading 上方 kicker/eyebrow」直接冲突。
- **动效降级**：`@media (prefers-reduced-motion: reduce)` 把全局 `transition-duration` 设为 `.01ms!important`；impeccable `audit.md` 会把「全局 0.01ms 抹掉状态反馈」列为动效敏感问题。
- **外部字体资源**：`styles.css` 第 1 行 `@import` Google Fonts（DM Sans、Noto Sans SC）。这是**既存**外部资源，不是本轮新增；是否继续依赖 CDN、是否升格为品牌承诺，见 T5。
- **320px 基线**：`body { min-width: 320px }`，为窄屏溢出检查提供既有下限。

> 以上均为「代码中已存在的事实」。按 C8，本阶段不把任何一条落实为改动；它们将在 D1（`audit`/`critique` 报告）与 D2（渲染基线验收）中作为可核对证据使用，并由 D3 在得到确认后决定是否修复。
