# C2 版本历史前端增量简报

> 状态：C2 产出（只出方案，不写代码）；本轮工作区产物，未提交、未推送。依据 `docs/frontend-skill-prompts.md` §3.3 C2、`docs/handoff-prompt.md` P1-8 与 `docs/api.md` §3.14 / 3.16 / 4.6 / 4.7 现有契约整理。不新增接口、不改后端、不假定用户已选定展示形态。

## Job（要解决的事）

让学生和教师能按提交版本追溯作业内容与附件：学生端凭回执链接回看本人历次提交并下载历史附件；教师端在看板中查看任一学生提交的历次修改并下载历史附件。前端只消费已定义的接口契约，不扩展业务范围。

## 现状核对（先于方案的事实）

P1-8 标注「前端『查看历次修改』UI 待做」，但该标注早于当前工作区状态。核对当前代码后确认，增量的大部分**已在工作区实现**（B3 / C1 阶段落地）：

- **客户端（`apps/web/src/api/client.ts`）**：`listSubmissionVersions()`（3.16，管理令牌）、`downloadSubmissionFile()`（3.14）、`download()`（4.7，凭 `receiptCode`）均已存在；`StudentReceipt` 类型已含 `versions: SubmissionVersion[]`，`SubmissionVersionList` / `SubmissionVersion` 类型已定义。**无缺口的客户端方法**。
- **教师端看板（`AssignmentDashboardView.vue`）**：行内「查看历次修改」按钮按需加载版本历史（懒加载，不阻塞看板首屏）；支持区域级错误与原地重试、空历史中性说明、历史附件经 3.14 下载（按文件粒度防并发）。
- **学生端回执（`StudentReceiptView.vue`）**：多版时折叠展示「查看历次修改（共 N 版）」并标记当前版本；历史附件经 4.7 凭回执码下载；`history.length <= 1` 时隐藏折叠入口；旧响应缺 `versions` 字段时正常渲染（`?? []` 兼容追加字段，符合 4.6「旧客户端忽略即可」的约定）。
- **测试**：看板 6 条版本历史用例（按需加载、历史附件下载、失败可恢复、空历史、重试成功）；回执 3 条（多版本下载、单版隐藏、旧响应兼容）。

因此本简报的作用是：把既有实现整理为方案基线，并把**尚未由项目所有者拍板的展示形态选择**全部列为待确认项；任何形态调整都在该基线上做增量。

## Outcome（期望结果）

- 教师与学生各自入口的版本历史状态（加载 / 失败 / 单版 / 多版 / 下载中 / 下载失败）都有可见解释与恢复动作（现状已满足）。
- 展示形态、入口位置、历史版本的数据深度等开放选择由项目所有者逐项拍板后，再做受控增量。
- 契约与安全边界不被突破：不新增接口、路由、依赖；`apps/api` 与 `docs/api.md` 零改动。

## Scope（范围与可选入口）

### 可选入口与可见范围

| 端 | 入口选项 | 可见范围 | 现状 |
| --- | --- | --- | --- |
| 教师端（管理令牌） | A1 看板表格行内「查看历次修改」折叠区 | 全班每个学生提交的全部版本（3.16） | **已实现（现用）** |
| 教师端 | A2 独立抽屉 / 弹层承载版本历史 | 同上 | 未实现；改动面与测试影响中等 |
| 教师端 | A3 独立路由页 | 同上 | 未实现；**与「不新增路由」约束冲突，排除** |
| 学生端（能力链接） | B1 回执页折叠「查看历次修改」 | 仅本人提交的版本（4.6 `versions`） | **已实现（现用）** |
| 学生端 | B2 提交页（`StudentAssignmentView`）提交后展示历史 | 仅本人本次会话对应的提交 | 未实现；需新状态与新测试 |

两端互不越权：3.16 仅管理令牌可达；4.6 / 4.7 仅凭 `receiptCode` 限本人提交；公开页面不渲染全班名单（契约 §5）。

### 下载路径复用（无新路径）

- 教师端历史附件：3.14 `downloadSubmissionFile(assignmentId, submissionId, fileId)`——服务端校验 `fileId` 同时属于该作业与该提交，历史版本 `fileId` 合法。
- 学生端历史附件：4.7 `api.download(fileId, receiptCode)`——服务端校验回执码属于该提交，历史版本 `fileId` 合法。
- ZIP 导出（3.13）**仅打包最新版本**（P1-8 明示）；历史版本是否纳入导出涉及后端契约变更，不属前端增量（见待确认项 3）。

### States（两种入口共用的状态矩阵）

| 状态 | 教师端（现状） | 学生端（现状） |
| --- | --- | --- |
| 未加载 / 懒加载 | 按需触发，不阻塞看板首屏 | 随回执一次返回，无独立加载 |
| 加载中 | 按钮转「正在读取…」并禁用 | 不适用 |
| 加载失败 | 区域级错误 + 原地重试，不吞错误码 | 随回执整体失败走页面级重试 |
| 仅一版 | 中性说明「这项目前只有一版提交…」（role=status，非错误） | 隐藏折叠入口（无历史可看） |
| 多版本 | 按版本号倒序平铺 | 倒序 + 「当前版本」标记 |
| 附件下载中 | 按文件粒度禁用按钮「正在下载…」 | 同左 |
| 附件下载失败 | 区域级错误，按钮恢复可重试 | 同左 |
| 旧响应无 `versions` | 不适用（走 3.16 独立接口） | 正常渲染，视同无历史 |

## Constraints（约束）

- 不新增接口、路由、依赖；不改 `apps/api`、`docs/api.md`；不消费 `GET /health`（T11）。
- 管理令牌仅存于 `sessionStorage`；能力链接（`shareCode` / `receiptCode`）只出现在路由参数与既有请求参数中。
- 展示遵循 `DESIGN.md` 与既有视觉基线；T9 排除多语言 / RTL / 深色模式 / 文本放大。
- 任何形态调整不得回退 C1 已建立的边界行为（空 Blob 不当有效文件、错误码不吞、空历史非错误等）。

## Open Decisions（待确认项，均未拍板）

1. **教师端入口形态**：维持看板行内折叠（现状，零改动）？还是改为独立抽屉 / 弹层（改动面与测试影响中等，移动端长列表更易滚动）？
2. **学生端是否增加提交页历史入口**（B2）：维持仅回执页（现状，回执链接是唯一可靠凭证）？还是在提交页提交成功后直接展示历次修改？
3. **ZIP 导出是否包含历史版本**：维持仅最新版（P1-8 现状，前端零改动）？还是需要纳入历史（涉及 3.13 后端契约与 `MAX_EXPORT_BYTES` 兜底，超出本轮前端范围，需另立后端任务）？
4. **版本数量多时的展示深度**：全量倒序平铺（现状，单班规模下可接受）？还是默认展示最近 N 版 +「展开全部」？
5. **回执单版时是否显示说明**：现状完全隐藏折叠入口（已测试）；是否需要「目前只有一版提交」的中性说明（与看板文案对齐）？
6. **看板是否标注当前版本**：回执已标「· 当前版本」；看板版本列表未标。是否需要对齐？

以上每项按「现状即默认零改动」理解；项目所有者逐项答复后，才进入受控增量实施（届时按本简报「会触及的文件与测试影响」评估改动面）。
